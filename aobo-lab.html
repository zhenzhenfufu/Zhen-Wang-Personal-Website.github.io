SIDERIUS

Open-source auto-ML agent for science · Rare AI Lab · Prof. Aobo Li (UCSD profile) · HDSI & Physics, UC San Diego

SIDERIUS turns a dataset and a research question into an iterative machine-learning experiment: it proposes models, writes them, trains and evaluates them, and uses what came back to decide what to try next. I am part of the team building it.

Try it on GitHub Paper · arXiv:2610.14024 Get started Give feedback

What it is

The name is an acronym — Scientific Inquiry, Design, Exploration and Reasoning Integrated Using multi-agent Systems — and the idea is in the first word. Most auto-ML optimises a number. SIDERIUS treats a run as research: the task is written down before anything starts, every iteration is recorded, and task-specific validity checks sit beside the score so a model that wins for the wrong reason gets caught rather than shipped.

You can drive it two ways. In a fixed workflow, a short Python file declares which research steps run, the advice each step gets, the budgets and the stop conditions. With orchestration, an LLM decides which step to call next and which model carries it out, inside the data-access rules and budgets you agreed on. The repository was built by Yue Ma with Prof. Li and the group, and is open source under the MIT licence.

My part

  • Orchestration. I run and tune the orchestration layer — the part that decides which research step comes next and which model carries it out — and test how it behaves over long runs.
  • End-to-end testing on real physics. The test bed is Project 8: estimating an electron's energy from the faint radio signal it emits while spiralling in a magnetic field. I replicated the agent's workflow on the full public data and worked out why the models it designs stop improving.
  • Guidance for the agent. I turned that diagnosis into structured physics guidance the agent can use when it proposes the next model, and built physics-based baselines to check the explanation was right rather than just plausible.
  • Feedback upstream. I file the defects I find back to the maintainers, and packaged the task's physics, contract and known pitfalls as a reusable skill so the next run starts from what the group already knows.

Why the problem is shaped this way

Physics time series — the data that carries evidence for dark matter, neutrinos and gravitational waves — hide a weak signal inside complex noise. An agent that optimises one or two numerical scores on data like that can take a shortcut, collapse to a degenerate solution, or fit the evaluation procedure itself, and still report a number that looks like progress. The reason I wanted into this group is narrow: physics is where a model that games its own metric eventually gets caught, because the thing it is supposed to find is real.

What I bring to it

At Pfizer I traced a review agent that was keying on how often a date appeared rather than on the rule it had been given — it would have scored well on anything but the right test. In my course planner, the model is not allowed to judge its own output; a deterministic checker does, and it names the rule that broke. Both are small versions of the same question this group asks at a scale that matters: how do you know the thing you built is actually right?

Use it, and tell us what broke

SIDERIUS is open source and the point is for people outside the group to use it. If you have a dataset and a question, start from the repository — your own coding agent can set it up with you — and open an issue when something is unclear or wrong. I am also happy to hear about it directly at zhw124@ucsd.edu.

The paper reports the agent's own results, including Project 8. The results of my work on top of it are unpublished and belong to the group, so they stay in the lab until they are written up.
