UCSD Course Planning Agent

Design, code and evaluation · Live demo ↗ · GitHub ↗

A language model is good at reading "I want to specialise in machine learning" and picking sensible courses. It is unreliable at the other half of the job: holding a 68-node prerequisite graph in its head. So in this planner the model does not get to decide whether a plan is legal. Code does.

Reading a graph out of prose

Catalog text was never written to be parsed. "Prerequisite: DSC 20" and "Prerequisite for DSC 20" point in opposite directions; "accepted as an alternative to DSC 140A" is not a prerequisite at all, though an early version of my parser read it as one and inverted the edge. The parser is now direction-aware, handles AND-of-OR groups, seven substitution rules, and abstract requirements like "a probability course", and reports references it cannot resolve instead of dropping them silently.

Replacing the app's hand-maintained edge list with the parsed graph closed a 25-edge drift between two sources of truth that had been diverging for months.

Retrieval that respects structure

The first version stuffed 31 KB of catalog into every prompt. It now retrieves by embedding similarity and then expands one hop along the dependency graph, which brings 8–13% of the catalog per query and guarantees that a retrieved course's prerequisites are in context. Similarity alone misses them: DSC 40B is structurally essential to a question about DSC 100 and reads nothing like it.

The part that actually moved the number

A deterministic checker verifies ordering, unit caps, duplicates, concurrency exceptions and OR-groups, and returns which rule broke rather than a score. Asked for a whole multi-quarter plan in one shot, the model was legal 40% of the time across 20 planning tasks. Generating one quarter at a time against a recomputed eligible set took that to 100% — at 2.65 model calls per task against 1.90 for the one-shot version. The checker is itself regression-tested against nine plans with known verdicts, so a bug in the judge does not masquerade as a better model.

The row worth reading twice is the second one. Feeding violations back as a repair signal is not enough on its own — the one-shot arm still failed 6 of 20 after repair. What fixed it was removing the illegal choices before the model chooses, at a real cost: 2.65 calls per task against 1.90. The validator itself is regression-tested on nine plans with known verdicts, 9 of 9.

What this is not

  • One department's catalog, parsed at one point in time. It is not an advising system and should not be trusted as one.
  • The 40% baseline is my own one-shot arm, not a published benchmark; both arms use the same model and the same 20 tasks.
  • No human evaluation — "legal" means the validator accepts it, not that a student would like the plan.
